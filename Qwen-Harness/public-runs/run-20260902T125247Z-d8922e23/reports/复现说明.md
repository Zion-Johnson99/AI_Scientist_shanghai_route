# 复现说明

本次运行的全部产物都在同一个 run 目录内，复现不依赖任何付费接口，也不依赖仓库里已有的三个业务模块。

run 目录（相对仓库根）：

```
Qwen-Harness/runtime/runs/run-20260902T125247Z-d8922e23/
```

下文所有路径都相对该 run 目录，源码根记作 `workspace/source/`。

## 一、环境要求

| 项 | 版本或说明 |
| --- | --- |
| Python | 3.11.15 |
| uv | 0.11.26，全部命令都用 `uv run --no-project`，不建虚拟环境、不装本地依赖 |
| Node.js | v24，用于 `node/` 下的契约测试和 DOM stub 冒烟测试 |
| 网络 | 只在“第一步取数”时需要，用于 OSM 与 Open-Meteo 公开接口 |
| 密钥 | 不需要。任何 `DASHSCOPE_API_KEY`、`OPENAI_API_KEY` 都不参与本次流程 |

所有命令都要在清除密钥变量的子进程里执行，这样即便宿主环境里存在这两个变量，也不可能被误用：

```bash
env -u DASHSCOPE_API_KEY -u OPENAI_API_KEY <命令>
```

## 二、第一步：取数（需要网络，已完成，可跳过）

```bash
env -u DASHSCOPE_API_KEY -u OPENAI_API_KEY uv run --no-project python commands/fetch_osm4_api.py
```

数据来源与口径：

| 数据 | 来源 | 口径 |
| --- | --- | --- |
| 徐汇区行政边界 | OSM relation `1278188`，`boundary=administrative` + `name:zh=徐汇区`，`admin_level=6` | 47 个 member，其中 33 条 outer way 串成 316 个顶点的闭合环 |
| 路网 | OSM 官方 API 0.6 `/api/0.6/map?bbox=w,s,e,n`，返回原始 OSM XML | 按 `121.3868848,31.102562,121.4719269,31.2220274` 切成 6×6 共 36 格，遇到 “too many nodes” 递归细分；36 格全部成功 |
| POI | 同上 OSM 官方 API | 3696 个 element |
| 气象 | `https://api.open-meteo.com/v1/forecast` | 区内 4 个散布点，`timezone=Asia/Shanghai`，`forecast_days=2` |

坐标系：全链路统一使用 `CRS84/WGS84 (lon,lat)`，即经度在前、纬度在后。刻意不使用 GCJ-02，也不加载任何需要 GCJ-02 纠偏的瓦片服务，因此边界计算前后不需要投影转换，只在 `routes/road_graph.py` 里用 `assert_crs` 做一次声明校验。

## 三、第二步：生成路线组合

```bash
cd Qwen-Harness/runtime/runs/run-20260902T125247Z-d8922e23
env -u DASHSCOPE_API_KEY -u OPENAI_API_KEY uv run --no-project python commands/smoke_routes.py \
  > commands/smoke_routes.log 2>&1
```

产物写入 `workspace/source/xuhui_route_builder/data/web/`，包括 `route_catalog.json`、`xuhui_routes.geojson`、`xuhui_boundary.geojson`、`xuhui_entries.geojson`、`poi_catalog.json`。

这一步是全流程里最慢的，单次约 5 分钟。

生成过程是确定性的：不带随机种子，也不读时钟。两次独立运行得到的计数器逐项相同，因此任何一次改动的效果都可以直接归因，不需要重复取样。

三种运动各自构建一张无向加权路网，规模记录在 `commands/smoke_routes.log` 的 `graph_stats` 中：

| 运动 | 节点 | 边 | 采用 way | 排除 way | 路网总长 |
| --- | --- | --- | --- | --- | --- |
| walk | 10819 | 12234 | 3001 | 256 | 526.153 km |
| run | 10716 | 12116 | 2950 | 307 | 524.154 km |
| bike | 7815 | 8655 | 2120 | 1137 | 470.883 km |

bike 排除 1137 条 way 是正确行为而非缺陷：`footway`、`pedestrian` 等步行专用道对骑行不可用，但两类路网总长只差约 56 km。

## 四、第三步：环境网格与路线暴露

```bash
cd workspace/source
env -u DASHSCOPE_API_KEY -u OPENAI_API_KEY uv run --no-project python -m environment \
  --generated-at 2026-09-02T13:30:00Z
```

`--generated-at` 必须显式传入，模块内部禁止自行读时钟，这样同一批输入永远得到同一份 dashboard。

54 格网格覆盖上述 bbox，6 行 × 9 列，单格面积约 1.981 km²，其中 29 格落在徐汇区边界内。米制换算用局部等距圆柱投影，多边形面积用鞋带公式。

字段分三类，`environment/__init__.py` 的 `FIELD_SPECS` 逐字段标注了单位与来源等级：

- 实测：`pm25_ug_m3`、`aqi_us`、`temperature_c`、`feels_like_c`、`humidity_pct`、`wind_speed_kmh`、`wind_gust_kmh`、`precipitation_mm`，来自 Open-Meteo。
- 从公开地理数据确定性计算：`green_ratio_0_1`、`water_ratio_0_1`、`road_density_km_per_km2`、`major_road_density_km_per_km2`。
- 代理量，只作序数使用：`traffic_exposure_0_1 = min(1, major/20)`；`noise_proxy_db = clip(38 + 12·log10(1+major) + 4·log10(1+road), 35, 85)`，单位写作 `dB_proxy`，明确表示这不是实测声压级，也不作健康效应估计。

## 五、第四步：评价矩阵、网页载荷与发布

```bash
cd workspace/source
env -u DASHSCOPE_API_KEY -u OPENAI_API_KEY uv run --no-project python scripts/generate_all.py --stage evaluation
env -u DASHSCOPE_API_KEY -u OPENAI_API_KEY uv run --no-project python scripts/build_web_payload.py \
  --generated-at 2026-09-02T13:30:00Z
```

`generate_all.py` 支持 `--stage` 取 `routes`、`environment`、`evaluation`、`web`、`checks` 或 `all`，按依赖顺序串起来。

五个评价维度的权重固定为 `environment_health` 0.30、`sport_match` 0.20、`access_convenience` 0.15、`route_quality` 0.20、`user_preference` 0.15，权重文件的 SHA-256 是 `ccf6151ac8fcc22e1341516fbfc7292673addbbb9ec602cf513c499e477d47b8`，API 的 `/health` 会回显这个值以便核对。

数据可靠度乘子：实测 1.0、推导 0.9、估计 0.75、不可用则该维度剔除并把权重重新归一到其余维度上；若没有任何维度可用，`data_reliability` 记 0.0 而不是空值的 1.0。

网页地图不用瓦片服务，而是用自带的 SVG/canvas 渲染器直接绘制真实徐汇边界和路网上下文。这是刻意的架构选择：不引入 GCJ-02 与瓦片 CDN 依赖，渲染结果确定、可离线、可测试，也构成本次运行独立的视觉语言。

完整 14 项契约（pytest × 3、Ruff × 4、Pyright × 4、Node 契约测试、评价 API、浏览器验收）：

```bash
env -u DASHSCOPE_API_KEY -u OPENAI_API_KEY uv run --no-project python scripts/run_quality_gates.py
```

`check_route_spatial.py` 不信任生成管线自己写下的指标。它从发布的 GeoJSON 坐标重建 `RouteInput`，重新推一遍权威门禁 `gates.evaluate_route`，并要求重算值与 catalog 里存的值在 2% 内一致。这样生成器的 bug 不会被同一套指标掩盖成“通过”。

`check_secret_scan.py` 扫描整个 run 目录的文本文件，检查密钥形状、凭据赋值、用户主目录绝对路径和编造的百炼 request/task ID。它的报告里只描述规则形状，不回写正则原文——否则报告本身会匹配自己写的规则，这道门禁永远无法第二次通过。`.env` 只记录是否存在，扫描器从不打开它。

## 九、已知的复现陷阱

1. **不要用 Git Bash 的 `curl` 测评价 API。** `curl -d` 会重新编码含中文的 JSON body，把正常请求报成 400。`scripts/check_evaluation_api.py` 因此只用 urllib。
2. **后台命令的退出码会掩盖实质失败。** 一律把 stdout 重定向到日志文件再追加 `echo "EXIT=$?"`，然后读日志里的 portfolio 判定，而不是只看退出码。
3. **`scripts/` 下的检查脚本要以 `python scripts/xxx.py` 方式运行。** 此时 `sys.path[0]` 是 `scripts/`，看不到上一层的第一方包，所以每个脚本都显式把源码根插进 `sys.path`。
4. **`math.floor`、`math.ceil`、`round` 外面不要再套 `int()`。** Python 3 里它们对 float 已经返回 int，Ruff 的 RUF046 会报冗余转换，而且这一条被归为需要 `--unsafe-fixes` 的隐藏修复，只能手改。
5. **Ruff 没有启用 E501 和 PLC。** 长行不报错，但写 `# noqa: PLC0415` 会因为 RUF100（无用 noqa）反而报错。
6. **Pyright 的 `include` 不含 `Qwen-Harness`。** 要检查它必须在命令行显式传路径，否则会被静默跳过。
