# 花粉与噪声接入最终方案

> 供执行 Agent 使用：按任务顺序开发，每个任务先写失败测试，再完成最小实现和本地验证。

**目标：** 在现有温湿度、天气、空气质量和 PM2.5 数据基础上，增加徐汇区约 1 km 花粉风险和约 100 米道路段噪声风险，最终按 `route_id` 形成多源路线暴露结果。

**架构：** Google Pollen 在 54 个 PM2.5 网格中心提供日级花粉背景，华风天气与沿线植被生成派生花粉评分；噪声使用道路、POI、绿地水体和声环境功能区生成静态及时段风险。两类结果映射到路线段后写入 `route_environment.json`。

**技术栈：** Python 3.10 及以上、requests、GeoPandas、Shapely、NumPy、pytest、Ruff、Pyright。首期复用现有依赖，不增加新的第三方包。

## 一、现有基础与边界

`weather_api_data` 已覆盖 14 个路线入口、11 个空气质量输出区和 54 个 PM2.5 网格，具备请求预算、标准化、历史库和 JSON 导出能力。`xuhui_route_builder/data/web/xuhui_routes.geojson` 包含 90 条 `LineString` 路线及稳定 `route_id`，当前 `route_environment.json` 只有数据契约。

Google Cloud 中的 `pollen api key1` 已限制到 Pollen API，并已确认项目启用结算。高德交通态势属于高级服务，当前账号未开通；首期噪声模型不读取高德交通接口，也不依赖高德 Web 服务 Key。

路线 GeoJSON 使用 GCJ-02，Google Pollen 请求使用 WGS84。空间处理先把路线坐标转换为 WGS84，再使用 EPSG:32651 完成米制切段、缓冲和长度计算；网页展示继续使用原始 GCJ-02 路线几何。

## 二、Google 花粉接入

### 2.1 数据能力与展示边界

- 接口：`https://pollen.googleapis.com/v1/forecast:lookup`
- 空间分辨率：最高约 1 km。
- 时间分辨率：日级，当天及未来最多 4 天，共最多 5 个日值。
- 中国覆盖：当前以草类花粉为主；树木和杂草缺失时记录为 `no_data`。
- 产品用途：区域花粉背景、过敏提示和路线相对风险排序。

比赛页面继续使用高德底图，仅展示多源计算后的 `pollen_risk_score`，不叠加 Google 原始花粉热图或原始指数图层。花粉评分区域显示 `Includes data from Google Maps`；原始响应只参与本轮内存计算，不进入 SQLite、GZIP 归档和 Git。派生评分保留来源、日期、有效期、空间尺度和 `estimated=true`。

### 2.2 54 网格采样与调用控制

复用 `pm25_grid_latest.json` 中 54 个 WGS84 网格中心作为 Google 查询点，使花粉和 PM2.5 使用一致的徐汇空间索引。54 个点属于本项目采样格网，Google 原生网格边界可能不同，因此输出使用“约 1 km 点位采样”的表述。

密钥只写入本地 `.env`：

```text
POLLEN_ENABLED=false
POLLEN_API_KEY=
POLLEN_MAX_CALLS_PER_RUN=60
POLLEN_MIN_INTERVAL_SECONDS=1.0
```

真实验证分两步进行：

1. `probe-pollen --grid-id XH_PM25_G001 --confirm-pollen-probe` 只发出 1 次请求，检查徐汇坐标、日期、草类指数、缺失字段和错误结构。
2. 单点通过后运行 `refresh-pollen-grid`，按 54 个网格中心请求并生成派生评分，单轮预算上限为 60 次。

花粉预算与华风单轮 150 次上限分别统计。每日刷新 1 次约为每月 1620 次请求；请求结果按坐标和业务日期去重，同一轮不重复查询相同网格。

### 2.3 花粉风险与路线差异

花粉风险包含三组信息：Google 草类花粉作为区域背景，华风风速、降雨、湿度和天气作为时间修正，沿线草地、公园和绿地覆盖率作为空间修正。首版权重写入 `config/pollen_model.json`，Google 背景占 70%，天气修正和植被修正各占 15%，后续根据徐汇实测或专家评审调整。

每个约 100 米路线段关联所在花粉网格，再按路段长度汇总到路线。不同路线通常会因经过网格、绿地比例和天气修正产生差异；共用相同网格和相近环境的路线允许得到相同或接近的评分，不人为制造逐路线唯一值。

输出字段包括 `grid_id`、`segment_id`、`pollen_risk_score`、`risk_level`、`forecast_date`、`source`、`spatial_resolution_m`、`confidence` 和 `estimated`。API 缺失时只使用天气与植被代理，并把状态降为 `partial`。

## 三、无交通 API 的噪声模型

### 3.1 首期输入与评分

首期输出 0 至 100 的 `noise_risk_score` 和低、中、高风险等级，输入包括：

- 上海声环境功能区背景。
- OSM 道路等级、车道、限速、步道、绿道、铁路和路口。
- 到快速路、主干路、高架及轨道交通的距离。
- 商业、交通枢纽和公共服务 POI 密度。
- 公园、滨水步道、绿地和水体覆盖修正。
- 工作日早晚高峰、日间和平峰等时段情景。

初始权重为道路等级 30%、主干路高架及铁路距离 25%、POI 与交通枢纽 15%、路口密度 10%、声功能区 10%、绿地水体降噪修正 10%，全部写入 `config/noise_model.json`。时段系数只提供情景估计，输出继续标注 `estimated=true`。

高德交通速度与拥堵状态留作后续增强项。首期不设置 `AMAP_TRAFFIC_API_KEY`，接口缺失也不降低静态模型运行状态；置信度根据空间特征完整度和实测校准覆盖确定。

### 3.2 四条路线实测校准

校准路线覆盖徐汇滨江、上海植物园、衡复风貌区和漕河泾。每条路线选择约 6 个点，覆盖安静步道、支路、商业街、主干路和高架附近；早晚各测一次，连续 3 天，每次记录至少 60 秒等效 A 声级。

```text
route_id,point_id,longitude,latitude,measured_at,laeq_db_a,duration_seconds,device,traffic_state,weather_note
```

校准程序按整条路线划分训练与验证数据，输出 MAE、RMSE、样本覆盖和分区误差。MAE 达到 5 dB 以内且四类区域未出现持续同方向偏差时，再增加 `noise_estimated_db_a`；此前只展示风险等级、时段情景和置信度。

NoiseCapture 稀疏点可用于外部对照。NoiseModelling 需要车流量、车型、速度、建筑物和地形等输入，首期暂缓接入，避免用缺失输入生成伪精确分贝。

## 四、路线分段与结果融合

路线按约 100 米切分并生成稳定 `segment_id`。每段关联 PM2.5 网格、花粉派生评分和噪声风险，再按实际长度汇总；100 米代表计算切段尺度，花粉独立信息尺度仍约 1 km，噪声属于道路特征代理。

新增输出：

- `runtime/exports/pollen_grid_scores.json`：54 个网格、最多 5 天的派生花粉评分。
- `runtime/exports/noise_segments.json`：道路段噪声特征、时段风险和置信度。
- `runtime/exports/route_environment.json`：按 `route_id` 汇总的 PM2.5、花粉、噪声和来源说明。

现有 `environment_regions.json`、`environment_latest.json`、`environment_hourly.json`、`pm25_grid_latest.json` 和 `pm25_grid_forecast_24h.json` 保持原结构。新增记录统一保留业务时间、获取时间、有效期、空间尺度、状态、置信度和估算标记。

## 六、错误处理与边缘情况

- 花粉 API 返回 401、403 或 429 时停止本轮网络请求，保留脱敏错误、调用次数和 `Retry-After`。
- 中国缺少树木或杂草花粉时保留 `no_data`，不使用草类数值填充。
- 54 个采样点出现相同值时如实保留，相邻路线评分允许重复。
- 路线短于 100 米、跨多个网格或属于闭合环线时按实际长度汇总。
- OSM、POI 或实测数据缺失时输出 `partial` 并降低置信度。
- 缺少实测噪声时不生成 `noise_estimated_db_a`。
- 密钥、完整认证 URL、Google 原始响应和原始定位响应不进入 Git、日志或历史库。
