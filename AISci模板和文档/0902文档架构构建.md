## 三、项目故事

城市步行、跑步和骑行活动持续增长，低碳慢行空间为户外运动提供了基础。运动者选择路线时，除距离和通行条件外，还会同时受到PM2.5、花粉、噪声、天气、绿地水体、沿途服务、接驳距离和个人健康敏感因素影响。

已有健康导航研究已经证明PM2.5数据能够参与低暴露路线规划，相关研究主要围绕单一污染物展开。真实户外运动场景包含多种环境暴露与个人偏好，现有方法缺少统一的数据处理、路线评价、个性化推荐和实验验证流程。(需要把具体的论文摆进去做分析，详细参考)

项目以徐汇区为首个研究区域，形成步行、跑步和骑行各30条、共90条已验收路线，将路线与54个约1公里环境网格、天气、空气质量、PM2.5、花粉、噪声、绿地水体、POI和接驳距离关联。用户输入运动方式、目标距离、出发位置和关注因素后，系统输出首选路线、两条备选路线、推荐理由、风险提醒、路线详情和前往起点的导航。

项目进一步使用Qwen-Harness组织证据、假设、实验设计、模块执行、指标计算、反馈判断和报告生成，将抽象科研流程转换为可运行代码、可复查日志和可交互地图产品。

## 四、项目解决的问题

项目解决的问题建议统一表述为：

> 面向城市户外运动场景，研究如何在路线长度、额外绕行、接驳距离和安全条件合理的范围内，融合PM2.5、花粉、噪声、天气、绿地水体、路线质量和个人偏好，选择综合环境风险较低、需求匹配度较高的路线，并形成由千问驱动、可复现的实验评价与反馈流程。

项目价值分为三个层面：

1. 科学层面：检验多源环境融合是否能够改善候选路线中的健康路线选择。
2. 工程层面：建立路线、环境、评价和网页四个模块之间稳定、可检查的数据链路。
3. 应用层面：把复杂的环境暴露和推荐结果转化为普通用户能够查看和操作的地图产品。

低碳用于说明应用场景和社会价值。科学结论聚焦健康路线选择效果，当前研究范围未纳入个人碳减排量核算。

## 五、“距离和绕行成本受限”的通俗解释

该表述表示系统推荐环境更好的路线时，仍要尊重用户原有的运动距离和时间需求。

- 距离限制：用户希望完成5公里运动，推荐路线应保持在5公里附近。目标距离偏差上限为15%时，可接受范围约为4.25—5.75公里。
- 绕行限制：健康路线相较最短可行路线可以稍长，额外路程控制在20%以内。
- 接驳成本：用户当前位置到运动路线起点的距离和时间，单独进入到达便利维度。

示例：A路线长5公里但靠近主干道；B路线长5.4公里，绿地更多且噪声风险较低。B路线仍然符合用户的运动目标，系统可以优先推荐B。环境条件较好的路线若长达8公里，则已明显偏离用户原来的运动计划。

文档中可采用以下简化表达：

> 在路线长度相近、额外绕行合理的前提下，选择环境更健康、更符合个人需求的路线。

## 六、科学问题与主假设

### 6.1 科学问题

> 在路线距离和安全条件相近的情况下，多源环境信息与个人偏好能否帮助系统选出综合环境风险更低、需求匹配度更高的户外运动路线？

### 6.2 主假设

正式表述：

> 在附加距离不超过20%、目标距离偏差不超过15%的条件下，多源个性化路线模型相较最短可行路线、PM2.5单源模型和多源非个性化模型，能够降低综合环境风险并提高个人偏好匹配度。

通俗表述：

> 对于距离相近的户外运动路线，同时考虑PM2.5、花粉、噪声、天气、绿地水体、到达距离和个人偏好，比只看最短距离或只看PM2.5，更有机会选出综合环境风险较低、用户更愿意选择的路线。

### 6.3 实验需要回答的问题

1. 推荐路线是否保持合理距离和绕行范围。
2. 综合环境风险是否优于最短路线和PM2.5单源路线。
3. 推荐结果是否更符合用户对安静、绿地、低花粉、低污染和沿途服务的偏好。
4. 数据缺失、数据过期或模型服务异常时，系统能否给出稳定、可追溯的降级结果。

### 6.4 结论边界

研究结论限定在徐汇区当前90条候选路线及现有环境数据范围内，评价对象是候选集中的路线选择效果。项目当前未研究疾病发生率、临床健康结局、个体真实吸入剂量和其他城市的普遍效果。

## 七、四个代码模块与Qwen-Harness

### 7.1 路线构建模块

正式链路为：

> 路线种子 → 高德路径缓存或在线生成 → 几何验证 → 路线组合验收 → 真实POI合并 → Web路线数据

路线种子记录真实入口、途经点、运动方式和路线形态。路线生成后依次检查行政边界、距离、折返、分支、自交、环线拓扑、三种运动数量、距离档、路线形态和POI覆盖。最终形成步行、跑步和骑行各30条路线，并为网页筛选、路线详情和接驳导航提供数据。

### 7.2 多源环境数据模块

数据来源和用途包括：

- 和风天气：当前天气、未来24小时天气、生活指数、预警、AQI和污染物信息。
- 上海空气质量站点与CHAP：形成PM2.5站点校正和约1公里空间背景。
- Google Pollen：提供当天及未来数日花粉背景。
- 上海噪声在线信息与空间代理：结合道路等级、交通邻近、POI、路口、绿地和水体形成0—100噪声风险代理。
- 路线与POI数据：用于路线空间匹配、沿途服务和接驳评价。

数据主链路为：

> 多源采集 → 字段与时间统一 → 54个环境网格 → 路线路段匹配 → 按实际经过长度汇总 → 90条路线暴露结果 → 评分与网页数据包

当前公开网站采用分层更新：Cloudflare每15分钟检查天气主刷新，空气质量执行小时级更新，每日执行完整环境更新与网页发布。花粉属于日级背景，噪声属于风险代理。上游异常时保留最近有效结果，并使用`partial`、`stale`、`no_data`等状态标记数据质量。

### 7.3 评价与千问推荐模块

推荐链路为：

> 用户画像与自然语言需求 → 安全检查与硬约束 → 五维评分 → 相似路线去重 → 前5条候选 → 千问审核与解释 → 首选及备选路线 → 本地排序降级 → 结果记录

硬约束包括运动方式、目标距离、搜索范围、路线形态、安全风险和数据可用性。默认平衡目标的五维权重为：环境健康35%、运动匹配25%、到达便利20%、路线质量10%、兴趣服务10%。环境维度内部权重为：PM2.5 45%、噪声35%、花粉20%。不同目标可以切换健康环境、距离训练、放松、风景、亲子和就近等权重配置。

Python负责硬约束、确定性评分、排序、数据状态和回退逻辑。千问负责理解自然语言需求、审核候选路线、生成推荐理由和风险提醒。模型服务异常时，系统继续返回本地评分结果。

### 7.4 网页前端模块

网页包含“帮我推荐”和“浏览路线”两条主线：

- 帮我推荐：选择运动方式、距离、出发位置、健康关注和兴趣偏好，调用推荐服务，展示首选与备选路线。
- 浏览路线：按运动方式、距离和偏好筛选90条路线，地图和路线列表同步更新。
- 路线详情：展示距离、时长、路线形态、沿途地点、环境风险、推荐理由和出行提示。
- 地图交互：支持地点搜索、设备定位、地图点选、路线预览和健康地图图层。
- 接驳导航：从当前位置或指定地点规划步行、骑行到路线起点的路径，并展示分步指引。
- 千问路线助手：通过专门对话收集需求，保持筛选、推荐、地图和详情状态同步。

### 7.5 Qwen-Harness

Qwen-Harness负责组织科研闭环：

> 研究目标理解 → 来源登记 → 证据抽取 → 引用核验 → 缺口分析 → 假设生成与评审 → 实验设计 → 四模块执行 → 指标计算 → 反馈判断 → 科研报告 → 本地网页产物

当前主体结构采用“配置工作流 → 千问科研智能 → 工程生成与模块执行 → 实验反馈 → 证据与交付”五层组织：

1. **配置工作流层**：命令行入口读取 `harness.json` 和工作流配置，按依赖关系执行19个阶段；现有 `full-research`、`reproduce-existing` 和 `research-only` 分别服务完整生成、现有工程复现和纯科研规划。
2. **千问科研智能层**：问题定义、证据抽取、研究缺口、假设生成与评审、实验设计、反馈决策和报告生成均采用结构化输入输出，模型参数、提示词版本和调用审计随运行保存。
3. **工程生成与模块执行层**：完整生成模式下，千问先生成架构计划，再逐文件生成路线、环境数据、评价推荐和网页模块，源码写入本轮隔离目录 `workspace/source`；校验发现问题后进入修复循环，当前上限为两轮。复现模式读取现有模块，通过适配器统一路线、环境、评价和网页接口。
4. **实验与反馈层**：按照用户画像、基线方案和实验变体运行指标计算；反馈结果写入本轮派生配置，并回到数据、实验设计或模块执行阶段继续验证，仓库默认配置保持原状。
5. **证据与交付层**：每轮在 `runtime/runs/<run-id>` 保存状态、事件、阶段产物、Skills快照、输入输出哈希、实验结果、质量门禁和报告。最终发布只读取本轮生成目录，经过路径、密钥、引用和结果门禁后形成本地网页产品与报告包，现有四个工程目录保持只读。

当前主体代码和流程已经基本完成，真实千问全流程生成、完整浏览器验收及最终发布效果以最新运行记录为准。代码模块在文档中表述为“大模型辅助的人机协同工程产出”；涉及千问的科研步骤应对应百炼调用记录、模型配置截图和Harness运行日志。

### 7.6 项目专用Skills与通用Skills协作层

Harness会从 `.qoder/skills` 读取技能，并把本轮使用的技能文件和哈希保存到运行目录，便于复现。当前正式工作流固定调用六类项目技能：科研编排、证据与假设、路线工程、环境数据、评价实验和网页集成。

## 八、实验设计与当前结论

### 8.1 对照方法

- B0：最短可行路线，只考虑目标距离和基本可行性。
- B1：PM2.5单源路线，在可行候选中选择PM2.5风险较低的路线。
- B2：多源非个性化路线，融合多种环境数据，采用统一权重。
- B3：默认权重非个性化路线，使用评价模块的平衡配置。
- M1：多源个性化约束模型，加入个人敏感项、兴趣和接驳距离。

### 8.2 主要评价指标

- 距离约束通过率：推荐路线是否符合目标距离和绕行限制。
- 环境胜率：多源个性化路线是否同时优于最短路线和PM2.5单源路线。
- 偏好胜率：个性化路线是否优于多源非个性化路线。
- 数据可靠性：结果使用的数据是否完整、有效且具有来源记录。
- 无候选率：硬约束是否导致没有可推荐路线。

### 8.3 当前实验结果

当前最新运行属于离线夹具复现，网页发布阶段被跳过。实验共形成20个实验单元，距离约束通过率和绕行合规率均为1.00，环境胜率和偏好胜率均为0.50，低于0.60的预设门槛，各方案在当前夹具中的环境风险均值差为0。

当前适合使用的科学结论为：

> 现有实验验证了多源健康路线科研流程的可执行性、约束合规性和结果可追溯性；当前离线证据对多源个性化方案的效果提供有限支持，真实环境数据、更多用户画像和在线千问实验仍需继续复核。

现有实验报告中“多数画像上优于基线”的文字与实际数值存在冲突，正式文档采用指标结果作为主口径。若提交前完成真实千问运行和第二轮实验，应使用最新运行数据替换本节。

## 十一、写作与证据边界

1. 代码模块统一表述为“大模型辅助的人机协同工程产出”，千问完成的步骤绑定百炼调用截图、Harness日志和运行报告。
2. 原始数据、确定性程序计算、千问判断和人工意见在文档中分开呈现。
3. 路线环境结果属于空间估计或风险代理，结论限定在候选路线比较，不外推为个体真实吸入剂量或临床健康收益。
4. 当前离线实验的数值作为阶段性证据，真实千问运行完成后再替换对应结果。
5. 未执行的第二轮实验写入待验证调整和下一步研究，完成状态保持清晰。
6. 网页截图、代码路径、运行ID、报告路径和实验指标形成一一对应关系。
7. 30页版本提交前保留赛事FAQ关于页数更新的截图或页面存档，以便核对旧模板中的20页说明。
