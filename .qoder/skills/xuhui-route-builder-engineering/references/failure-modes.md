# Failure Modes

| 失败 | 现象 | 处置 |
| --- | --- | --- |
| 数据文件缺失 | `route_catalog.json` 等不存在或不可解析 | `status=error`，列出缺失项，不继续后续操作 |
| 数量不符 | 总数不是 90 或某模式不是 30 | 阻塞交接；报告差异；不自动重生成 |
| ID 不一致 | 目录与 GeoJSON 的 `route_id` 集合不等或重复 | 阻塞；先定位写入者冲突，再修复 |
| 几何验收失败 | 假环、折返、扭曲、距离带越界 | 退回骨干设计（`optimize-xuhui-routes`），先于 POI 与显示 |
| 重复路线 | 正向/反向重复几何 | 模式交接前必须检出并处理 |
| 网络未授权 | `validate-routes` 需在线核验但未授权 | 标记 `skipped` 并说明；不静默降级为通过 |
| 上游限流/超时 | 地图服务 429、504、超时簇 | 停止该来源，保留路线 ID、参数、缓存状态和错误上下文 |
| 坐标系混用 | GCJ-02 与 WGS84 未转换就比较 | 先统一到比较坐标系，再重算 |
| 视觉存疑 | 本地指标通过但视觉混乱 | 保持 `needs_review`，不标 `accepted` |
| 写入冲突 | 多个进程写共享数据文件 | 单一写入者原则；中止并报告 |

原则：路线重建是高成本操作。Harness 默认只读取、快照和验收；生成与候选导出在 v1 禁用，出现相关需求时上报而不是绕过。
