# 0830 帮我推荐部分 UI 优化计划

_面向新开发会话的实施说明，默认使用“选项 + 一句话”，并提供可进入、可关闭的千问聊天工作区_

---

## 🎯 目标与范围

本轮沿着一条主链路改造：**统一顶部入口 → 默认填写“选项 + 一句话” → 按需点击千问图标进入聊天 → 汇总偏好并筛选 → 总览三条路线 → 悬停预览 → 点击聚焦并查看详情**。

目标是让页面更像城市运动路线产品：地图占据主视觉，操作入口集中，文案简短，三条路线关系清楚，环境信息和个人档案按需展开。Komoot 的列表与地图协同选路、按运动方式调整规划、地图承担主要工作区等做法作为交互参考。[^1][^2]

![当前徐汇户外健康地图完整页面](assets/0830-recommendation-ui-references/01-current-page-overview.png)
_图 1：当前页面的完整状态，用于核对重复位置、密集标签、左侧信息层级和地图占比。_

本轮范围包括：

- “帮我推荐”快捷选择模式
- “问问千问”短对话模式
- 顶部位置、运动方式、环境和个人档案入口
- 推荐筛选进度和偏好摘要
- 三条路线总览、悬停联动、点击聚焦和详情面板
- 右上角环境弹层与右下角图层控件
- 桌面端、小屏端、键盘操作和动效降级

本轮暂缓：

- “浏览路线”页面的完整重构
- 动态生成路线几何
- 账号体系与跨设备档案同步
- 路线照片采集与版权授权流程
- 导航算法、环境数据生成和评分公式调整
- 远程发布、GitHub 推送与生产部署

## 📋 已确认的产品决策

| 决策 | 确认方案 | 页面结果 |
| --- | --- | --- |
| 推荐入口 | 默认展示“选项 + 一句话”，左侧工作台标题栏右侧加入千问图标 | 点击图标进入聊天，关闭后回到原表单 |
| 快捷选择 | 保留选项与一句补充需求 | 核心条件首屏展示，高级偏好折叠 |
| 千问对话 | 独立聊天工作区 | 示例开场，缺项时追问，右上角叉号关闭 |
| 位置 | 全站只保留顶部一个入口 | 搜索地点、地图选点共用同一状态 |
| 运动方式 | 放入顶部位置右侧 | 步行、跑步、骑行持续可见 |
| 环境 | 顶部右侧紧凑状态按钮 | 点击后展开当前、24 小时、指数详情 |
| 档案 | 首次填写后保存在本机 | 后续进入页面不重复弹出，可从顶部手动修改 |
| 推荐结果 | 初始同时展示三条路线 | 地图自动容纳全部路线，列表顺序固定 |
| 悬停 | 当前路线增强，其余路线降低强调 | 只做预览，不缩放、不打开详情 |
| 点击 | 地图聚焦当前路线 | 打开独立详情面板，原卡片保持原位置 |
| 返回 | 提供“返回路线总览” | 关闭详情并恢复三条路线完整视野 |
| 推荐解释 | 短句与可核验优势 | 移除长段模型判断、可信度徽标和全区同值提醒 |

> 📌 **稳定规则：** 三条推荐路线始终按接口的 `final_rank` 排列。点击第二或第三条路线只改变 `selectedRouteId`，不会重排卡片，也不会把该路线移入“首选路线”区域。

## 📍 页面结构与视觉系统

### 桌面端结构

页面分成四层：

1. **顶部工具栏**：品牌、位置、运动方式、环境状态、个人档案
2. **左侧推荐工作台**：默认选项表单、一句话补充、标题栏千问图标、聊天工作区、筛选进度或三条结果列表
3. **地图主画布**：路线几何、当前位置、起终点和地图控件
4. **路线详情面板**：用户点击路线后从结果列表右侧展开

顶部工具栏建议排列：

```text
[XH 标志] [上海交通大学徐汇校区 ▾] [步行 | 跑步 | 骑行]        [阵雨 30.2° · AQI 16 ▾] [个人档案 ⚙]
```

- 位置输入框宽度约 `300–380px`，地点名称保持单行省略
- 运动方式使用三个等宽图标按钮，点击后同步选项推荐与千问聊天
- 环境按钮显示天气、温度、AQI 和状态色，详情放入锚定弹层
- 档案按钮使用更精致的齿轮图标；悬停或键盘聚焦时，左侧滑出“个人档案”标签
- 位置辅助句、品牌副标题、第二处位置卡片、第二处档案入口全部移除

### 环境、档案与图层

- **环境弹层**参考 Komoot 顶部 `NEW` 菜单的锚定关系：按钮下方展开、圆角白底、轻阴影、点击外部或按 `Escape` 收起
- 环境内容继续复用“现在 / 24 小时 / 指数”，保留数据状态、业务时间和有效期
- 环境按钮在预警时显示一枚小状态点，常态不增加说明文字
- 档案已保存时只展示摘要，如“日常运动 · 空气敏感”；点击后进入手动编辑
- 右下角图层入口改为白色紧凑按钮，点击后向上展开图层菜单，收起状态只保留图层图标与“图层”两字
- 环境弹层、档案弹层和图层菜单同一时刻只展开一个

### 状态持久化

- `location`、`route_mode`、快捷偏好和对话解析出的偏好进入同一个页面状态
- 进入千问聊天或点击叉号返回时保留已经填写的内容
- 从详情返回总览时保留三条结果和当前滚动位置
- 点击“重新推荐”时保留位置、运动方式、档案和上一次偏好，只展开可调整区域
- 页面刷新后恢复已保存档案并回到默认选项推荐；临时聊天记录和推荐结果按当前会话处理

## 💬 默认选项推荐与千问入口

### 快捷选择

顶部位置与运动方式已经确定后，左侧默认显示选项推荐。首屏只显示三个核心问题：

- **计划时间**：现在、两小时后、自定义
- **距离**：根据步行、跑步或骑行切换对应档位
- **主要目标**：综合均衡、健康环境、固定距离训练、放松、风景、亲子、就近

“更多偏好”折叠区继续保留：搜索范围、路线形态和兴趣需求。表单末尾持续保留一句补充需求输入框。敏感情况来自个人档案，不在每次推荐时重复询问。

左侧工作台标题栏右侧加入一个 `32–36px` 的千问图标按钮，位置参考 Komoot 路线列表右上角的小型聊天入口。按钮可使用千问标志，默认仅显示图标，避免占用表单空间：

```text
[帮我推荐]                                      [千问图标]

[计划时间] [距离] [主要目标]
[更多偏好]
[用一句话补充你的需求……]
[为我推荐路线]
```

千问图标提供 `aria-label="问问千问"`，悬停或键盘聚焦时显示同名短提示。点击后左侧工作台切换到聊天视图。页面首次打开、刷新页面以及关闭聊天后都显示“选项 + 一句话”。默认视图不放置大尺寸千问引导卡。

提交前在按钮上方显示一行摘要，例如：

```text
上海交大徐汇校区 · 步行 · 1–2 公里 · 公园放松 · 偏好安静
```

### 问问千问

千问聊天是面向路线任务的独立工作区，整体替换左侧选项表单。顶部显示“问问千问”和右上角叉号；点击叉号立即回到“选项 + 一句话”，顶部位置、运动方式、档案和已整理偏好保持原状。

聊天开场只保留一句问题、三个示例和一个输入框。用户点选示例后直接填入输入框，仍可继续修改。

建议示例：

- “从交大徐汇校区出发，散步一小时，想走安静、有树荫的环线”
- “帮我找一条 5 公里左右的跑步路线，空气好一点，沿途有厕所”
- “周末骑行 10 公里左右，想看滨江风景，最后回到出发点”

对话规则：

1. 顶部已有的位置和运动方式直接进入上下文，千问避免重复询问
2. 千问把自然语言转换为结构化偏好补丁，如距离、时间、目标、路线形态和兴趣
3. 缺少关键条件时每轮只追问一个问题，最多追问两轮
4. 条件齐全后显示“我理解的是”偏好摘要，用户确认后开始筛选
5. 用户随时可修改摘要中的单个条件，也可点击叉号回到选项推荐继续完成

示例对话：

```text
用户：想在附近跑一会儿，安静一点。
千问：你更希望跑 3–5 公里，还是 5–8 公里？
用户：5 公里左右。
千问：已整理：当前位置附近 · 跑步 · 约 5 公里 · 偏好安静。开始推荐？
```

千问回复保持两句以内，避免开放式闲聊、长篇分析和重复复述。每条回复优先推进一个决策。

### 两种入口共用的进度状态

开始推荐后，左侧用真实阶段替代空白加载卡：

1. **汇总偏好**：展示位置、运动方式、距离、目标和档案敏感项
2. **匹配路线**：显示正在应用距离、区域、形态与环境条件
3. **准备结果**：整理前三条路线并计算地图视野

阶段按真实任务完成事件推进，不显示推测百分比。千问审核发生降级时，仍使用 Python 排序并在结果顶部显示一条轻量提示。

指定 session 已生成匹配态方向稿，执行时保留“阶段进度 + 已选偏好 + 档案摘要”的信息结构，地图只承担轻量等待反馈，避免大面积空白。

## 🗺️ 三路线总览与详情

### 结果列表

左侧固定显示三张同级路线卡，第一张带“首选”小标签，第二、第三张只显示序号。每张卡保留：

- 路线名称
- 距离、预计时间、环线或单程
- 两项最有区分度的优势，如“滨江视野”“公园绿荫”“沿途厕所”“接驳较近”
- 一句不超过约 `36` 个中文字符的匹配说明

删除以下内容：

- 大段千问判断
- “数据可信度 53%”一类徽标
- “花粉全区同值”一类无法区分路线的标签
- “更近”“更长”这类缺少产品价值的单词标签
- 无来源的圆形占位图片

有来源且获准使用的真实路线照片才展示图片；图片缺失时收起图片区，文字自动补位。

### 地图联动规则

| 事件 | 地图表现 | 列表表现 | 详情表现 |
| --- | --- | --- | --- |
| 结果返回 | `fitView` 容纳三条路线 | 三张卡全部可见 | 关闭 |
| 悬停卡片 | 当前线加粗，其余线降至约 `0.16–0.24` 透明度 | 当前卡抬升并增强边框 | 关闭 |
| 离开卡片 | 恢复三条路线原始强调 | 恢复三张卡 | 关闭 |
| 聚焦卡片 | 效果等同悬停 | 显示键盘焦点 | 关闭 |
| 点击卡片 | `fitView` 聚焦当前路线，其余线隐藏或极弱显示 | 原顺序保留，当前卡选中 | 打开 |
| 关闭详情 | 恢复三条路线完整视野 | 保留原顺序 | 关闭 |

地图路线本身也支持悬停和点击，状态同步到左侧对应卡片。触屏设备没有悬停，第一次点击卡片直接进入聚焦详情。

### 路线详情面板

点击路线后，在结果列表右侧展开详情面板。内容顺序建议为：

1. 路线名称与关闭按钮
2. 距离、时间、路线形态和运动方式
3. 两至三项有数据依据的路线优势
4. 简洁路线概览或途经区域
5. 环境状态与必要提醒
6. “前往起点”主按钮
7. “返回路线总览”次按钮

详情面板继续复用现有接驳导航入口。推荐理由来自 `matched_preferences`、路线标签、接驳距离和有区分度的环境指标；千问只负责压缩为短句。原始环境值、时间和空间尺度放在可展开详情中。

## 🔌 千问接口与数据边界

### 现有链路

当前已有：

- `GET /api/v1/questionnaire`
- `POST /api/v1/recommendations`
- `GET /api/v1/health`
- 严格的 `UserProfile` 与 `RecommendationResult`
- Python 硬约束、评分、排序和千问审核降级
- 浏览器端 `recommendation-api.js`

新的对话模式增加一层**意图解析**，随后继续调用现有推荐接口：

```text
用户消息 → 千问结构化解析 → 偏好摘要确认 → UserProfile → Python 筛选与排序 → 千问审核前三候选 → RecommendationResult
```

### 新增接口建议

新增 `POST /api/v1/recommendation-intent`，每次提交当前消息、有限对话历史和顶部上下文。

请求示例：

```json
{
  "message": "想跑 5 公里，安静一点，沿途有厕所",
  "history": [],
  "context": {
    "location": {
      "label": "上海交通大学徐汇校区",
      "lng_gcj02": 121.433,
      "lat_gcj02": 31.200
    },
    "route_mode": "run",
    "profile": {
      "experience": "regular",
      "sensitivities": ["air"]
    },
    "preferences": {}
  }
}
```

响应示例：

```json
{
  "reply": "已整理为约 5 公里的安静跑步路线，并优先考虑沿途厕所。开始推荐？",
  "ready": true,
  "missing_fields": [],
  "preference_patch": {
    "distance_min_m": 4000,
    "target_distance_m": 5000,
    "distance_max_m": 6000,
    "interests": ["quiet", "toilet"]
  }
}
```

### 约束与降级

- Qwen 输出使用 Pydantic 严格模型校验，枚举和值域与 `UserProfile` 对齐
- 单条消息限制 `500` 字，对话历史限制最近 `6` 条，前端与服务端同时校验
- 对话阶段只生成偏好补丁，不生成路线 ID，也不改写 Python 的硬约束与排序
- 性别、密钥和原始档案文本不进入浏览器请求；只发送推荐所需的经验与敏感项
- 千问密钥始终保留在 Python 服务端
- 原始对话不写入普通日志；审计只记录请求 ID、耗时、模型、状态和错误类型
- 超时、鉴权失败、结构校验失败时保留已解析条件，提示用户切换快捷选择继续
- 环境暂停、无候选和服务异常沿用现有业务状态与错误卡片

### 浏览器验收

- `1440 × 900`：顶部入口完整，左栏与详情面板不遮挡路线主体
- `2560 × 1200`：地图保持主视觉，面板宽度不随屏幕过度拉伸
- `500 × 700`：顶部控件可横向收纳，结果与详情改为底部抽屉
- 键盘：`Tab` 可到达卡片，`Enter` 或空格进入详情，`Escape` 关闭弹层或详情
- 动效降级：`prefers-reduced-motion` 下无旋转、滑动和循环闪烁
- 触屏：点击卡片直接聚焦，返回按钮恢复三线总览

### 边缘情况

| 场景 | 预期处理 |
| --- | --- |
| 未选择位置 | 顶部位置控件获得焦点，保留已填偏好 |
| 地点搜索失败 | 支持地图选点与重试 |
| 千问问题含糊 | 每轮追问一个关键字段 |
| 千问超时或输出非法 | 保留已识别内容，引导切换快捷选择 |
| 推荐少于三条 | 展示实际数量，地图适配现有路线 |
| 三条路线高度重叠 | 使用线宽、描边与序号区分，悬停仍保持同步 |
| 快速移过多张卡 | 只采纳最后一个 `hoveredRouteId` |
| 点击备选路线 | 卡片顺序和“首选”标签保持原样 |
| 关闭详情 | 恢复全部推荐路线与原列表滚动位置 |
| 档案已保存 | 页面加载时不弹窗，顶部入口可手动打开 |
| 环境数据过期 | 显示状态与时间，避免当前实时口吻 |
| 路线照片缺失 | 收起图片区，无占位圆形 |
| 环境风险暂停 | 停留在暂停状态，不绘制可出发路线 |
| 导航失败 | 保留当前路线和详情，提供重试入口 |

### 完成标准

- 页面中只有一个位置入口和一个档案入口
- 位置、步行/跑步/骑行、环境和档案位于同一顶部工具栏
- 页面默认显示“选项 + 一句话”，左侧标题栏持续提供千问图标
- 点击千问图标进入独立聊天工作区，点击右上角叉号返回原表单
- 选项推荐与千问聊天均可生成同一种 `UserProfile`
- 进入聊天、关闭聊天、重新推荐和详情返回均保留偏好
- 推荐返回后地图初始同时容纳最多三条路线
- 悬停只改变强调层级，不触发缩放、重排或详情
- 点击路线后地图聚焦并打开详情，卡片仍在原位置
- “返回路线总览”恢复三条路线完整视野
- 环境详情继续提供“现在 / 24 小时 / 指数”
- 档案首次保存后不再自动弹出
- 页面不展示长段千问判断、可信度徽标和无区分度环境标签
- 千问失败时 Python 推荐链路仍可完成
- 密钥、原始聊天内容和敏感日志均未进入前端资源或审计输出
- 单测、静态检查、linter、formatter、类型检查和浏览器验收全部通过
