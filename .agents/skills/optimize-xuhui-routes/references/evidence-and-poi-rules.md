# 路线依据与 POI 规则

## 1. 证据层级

| 等级 | 来源 | 用途 |
| --- | --- | --- |
| A | 政府、公园、体育场馆和路线运营方官方页面 | 确认路线主题、开放语义、入口和官方母线 |
| B | 高德当前道路、POI、路径响应和 OSM 可通行路网 | 确认坐标、道路生成、服务设施和网络贴合 |
| C | Komoot 等社区实走或实骑记录 | 发现连续道路骨架和风险线索 |

官方母线提供空间语义。进入正式路线前，仍需当前道路生成、边界、通行限制和视觉复核。社区轨迹只承担线索角色。

## 4. 四类偏好与独立审计

正式偏好筛选使用以下四类：

- `coffee`
- `park_gate`
- `toilet`
- `convenience`

饮水点、运动驿站和自行车服务点保留为附加服务。四类偏好数量独立记录，不参与路线几何验收和 `validation_status` 计算。

每条路线沿线搜索四类偏好，并保存完整的 `preference_search_status`。状态值包括：

- `verified`：存在至少一个当前可核实设施，类型进入 `preference_hits`；
- `no_verified_match`：走廊内未获得当前可核实设施；
- `needs_review`：有候选设施，名称、坐标、开放状态或来源仍待核实；
- `source_failed`：数据源发生限流、超时或连续异常，保留查询上下文后暂停该批次。

最终报告统计零类、一类、两类、三类和四类覆盖。真实走廊内缺少设施时保留空结果。5 公里以上跑步线与 10 公里以上骑行线缺少 `toilet` 或 `convenience` 时输出补给告警，路线几何结论保持不变。

`preference_hits` 只从当前路线的核实 `nearby_pois` 生成。种子文件中的偏好字段仅表示检索意图，禁止直接进入筛选结果。

## 5. POI 空间规则

- 步行和跑步的咖啡、厕所、便利店补给使用轨迹两侧 100 米走廊。
- 骑行的咖啡、厕所、便利店补给使用轨迹两侧 200 米走廊。
- 公园真实开放入口在 100 米以内记录为 `along_route`，页面显示“公园入口”。
- 公园真实开放入口在 100–200 米记录为 `nearby`，页面显示“邻近公园·约 N 米”。
- `nearby` 公园还需核实步行连接；河道、快速路、围墙或封闭门区等明显阻隔进入复核，复核完成前不产生偏好命中。
- POI 仅承担服务、偏好和地图标记角色，不进入高德导航节点，也不驱动路线绕行。
- 公园中心点、普通绿地、住宅绿化和推测入口均不计入已核实覆盖。
- 相邻路线复用同一 POI，通过 `related_route_ids` 建立关联。
- POI 缺失时保留路线主骨架和空数组，记录覆盖缺口。

## 6. 热门区域覆盖

90 条组合覆盖徐汇区主要运动与城市漫游区域：

- 徐汇滨江与西岸；
- 龙华；
- 徐家汇；
- 衡复风貌区；
- 上海植物园；
- 康健园；
- 漕河泾；
- 华泾。

`popular_area_ids` 或路线名称、区域标签用于组合门禁的初筛。最终空间覆盖以路线全景、实际轨迹经过位置和入口证据为准。长距离骑行优先连接多个区域，短距离步行与跑步优先形成区域内部高质量路线，避免为了覆盖数量产生折返或假闭环。

## 7. 真实性字段

正式 POI 至少保存：

- 稳定 POI ID；
- 当前名称与类型；
- GCJ-02 坐标；
- 来源与原始响应路径；
- 查询或访问时间；
- 营业、开放或服务状态；
- 关联路线；
- 到轨迹的最近距离；
- `along_route` 或 `nearby` 路线关系；
- `verified` 或 `needs_review` 状态。

名称、坐标或状态缺失时标记 `needs_review`，不进入已核实偏好筛选。严禁使用泛化名称、推测营业状态或伪造示例 POI。

每条路线还保存四类搜索状态、`nearby_pois` 和 `preference_hits`。三者逐项一致：核实关联的类型进入 `preference_hits`，无核实关联的类型保持空结果。

同一来源存在多个 ID 时，还要按名称、坐标和设施实体检查物理重复。稳定 ID 去重后再跨路线复用，避免一个厕所、便利店或公园入口在同一路线重复展示。

## 8. 调用与缓存

1. 先查 `data/raw/amap`、现有 POI 目录和官方来源记录。
2. 按区域或路线走廊批量查询 POI，并跨路线复用。
3. 每批最多处理 5 条路线，共享同一走廊或入口集合。
4. 用唯一节点对缓存高德路径响应。
5. 高德原始路径、本地几何门禁和全景目视组成道路主证据；仅对通行性、运动模式或道路吸附存疑片段运行 Overpass。
6. 只重试失败或过期项。
7. 收到 `429`、`504` 或连续异常时停止该批次，保留路线编号、查询参数、状态和异常位置。
